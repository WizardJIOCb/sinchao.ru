# V2 — restaurant, discovery and return visits

Scope approved by the owner: all V2 features. The existing catalogue, theme,
accounts and staff permissions stay in place. No external messages are sent.

- Editable floor plan, seats and table availability, transactional specific-table reservations.
- Optional basket pre-order linked to a reservation; staff activates it on arrival.
- Rotating visit code behind permanent table QR links; guest membership, additional orders and waiter/bill requests.
- Equal bill shares calculated in kopecks, persisted payment receipts confirmed by staff. No card acquiring is simulated.
- Favourites, food preferences and explained recommendations based on available dishes and completed orders.
- Vietnam Food Journey and achievements calculated from completed, paid orders.
- Configurable events with capacity-controlled signup and cancellation.
- Gift certificate requests, staff confirmation of received payment, code and remaining balance, transactional redemption against delivery/pickup orders or table bill shares.
- Referral codes and a single reward after an invited customer's first completed paid order.

The initial seating plan is a labelled example until an operator verifies it.
The existing demo mode remains enabled. Actual seating, opening hours, operational
processes and promotion rules must be configured by the restaurant. Event content
is not invented; an empty list is shown until staff publishes an event.

Verification includes migration compatibility, ownership/staff restrictions,
capacity and payment concurrency, idempotency, browser customer/staff flows,
production build, CI and public deployment health checks.
